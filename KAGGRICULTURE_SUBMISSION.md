# AgriNexus OS — Kaggriculture submission\n\nThe repository now contains a competition-native main.py at the repository root.\n\n## System identity

**AgriNexus OS — Multi-Agent Autonomous Farm Intelligence**

**Tagline:** Specialist agents. One farm. Continuous adaptation.

## What changed\n\nThe original application is a useful autonomous-farm observability console, but it was not itself a Kaggriculture submission: its simulator used an abstract five-action API and did not model the real 10x10 grid, farm hands, animals, shared market, shed logistics, or Kaggle's agent(obs) contract.\n\nmain.py is now the actual submission entry point.\n\n## Policy architecture\n\n1. Safety / biological deadlines — rescue unwatered crops and unfed animals first.\n2. Production — harvest, care, water, fertilizer and placement.\n3. Standing-on-work dispatch — a unit already standing on a required tile acts before being moved.\n4. Economic portfolio — wheat protects feed; carrot, tomato, strawberry and melon are available to the crop portfolio agent; cows, sheep and geese provide milk, wool and eggs when market economics support them.\n5. Fertility loop — collect animal fertilizer and route it to high-leverage crops.\n6. Market throttling — sell continuously in bounded batches instead of creating a glut.\n7. Labor scaling — Fibonacci daily hire economics, capped at 11 hands.\n8. Land gating — neighboring quadrants are acquired only after liquidity, workforce and utilization gates pass.\n\n## Submission contract\n\nKaggriculture requires a root-level main.py exposing agent(obs) and returning farmer, hands and market action lists.\n\nThe policy uses no network calls, model downloads, external packages, files, or persistent state.\n\n## Important validation note\n\nThe development environment available here does not contain kaggle-environments, and outbound package installation is unavailable, so a real 720-turn simulator run could not be executed in this session. The code was designed directly against the official Kaggriculture observation/action mechanics and should be validated locally with the official environment before the final upload.\n\n## Final submission\n\nInstall kaggle-environments, run python -m py_compile main.py, then run a 720-step local match against starter before uploading main.py to Kaggle.\n\nThe competition final submission deadline is September 30, 2026 at 11:59 PM UTC; only the latest two submissions are tracked for final evaluation.
